# 改版進度（分支 `redesign-elem-jh`）

規格：`docs/redesign-spec.md`。這份檔案記錄實作決策與進度，讓之後接手的人（或對話壓縮後的 Claude）能接續。

## 實作決策

- 五條線沿用 id：`care` 二年級安親、`jh` 國中班導（九年級）、`teacher` 跑堂國中數學、`yun` 櫃台、`boss` 主任。
- **多樓層做法**：三層樓放在同一個平面上，以 X 方向偏移區隔（每層寬 36、間距 48：1F x∈[0,36]、2F x∈[48,84]、3F x∈[96,132]）。
  - 樓層由 `floorOf(x)` 判斷。
  - 只顯示玩家所在樓層的場景群組與人物。
  - 樓梯、電梯是 A* 尋路中的跨樓層連結（portal），走到連結點時直接瞬移到另一層的對應點。
- **格局由資料定義**（`src/layout.js`）：房間、門、家具、座位、命名地點（SPOTS）、區域（ZONE_RECTS）、招牌、樓梯電梯。
  - `world.js` 只負責依資料建出灰盒場景。
  - GPT 之後依同一份資料重做美術。
- **美術層**：分支中停用和舊座標綁死的部分，保留通用的材質、人物模型、家具外觀與效能合併。
  - 停用：`art.js` 的各房間細節、`art_models` 櫃台組、`art_phase2_env`／`light`／`story`。
- **人群改成時間表驅動**：每位背景人物有樓層、座位、到達時刻、離開時刻；舊的 `setCrowd`／`setKidCrowd`／`consistency*.js` 移除。
- **劇本**：先寫成資料（`src/lines/*.js` 的新內容），目標用 SPOTS 名稱與人物 id，不寫死座標。

## 效能備註

- `blockedAt` 改成依 x 分桶查 solids（三層樓的家具很多，舊的全表掃描讓國中生到班時一幀卡 300ms 以上）。
- 尋路拉直改成「從錨點往前延伸」，`los` 先篩掉離線段太遠的避讓點。
- 測試頁要用 `python3 build.py stub.js tests/test.html` 重建，`python3 build.py` 只會產生 index.html。

## 引擎小改

- 步驟的 `target`、`action` 可以是函式（依前一天的旗標決定找誰）。
- 跑堂老師第二天兩個班：`teachAt(G)` 決定上課時站哪個講台。
- `phaseOf` 的「收拾中」以最後一個劇情步驟為準，加班步驟不算。
- 尋路：終點在椅子這類家具裡時，1 公尺內所有空格都算終點（避免挑到被桌子圍住的角落）。課桌寬改成 1 公尺，走道才過得去。
